# 开发者复用 Prompt · 雪境漫游 Snowbound

将下面的任务说明交给开发者或编程助手，可基于本项目继续开发。先阅读实际代码与 `README.md`，以当前实现为准。

---

请基于这个工程开发一款可以在浏览器游玩的 3D 滑雪小游戏「雪境漫游 · Snowbound」。技术栈为原生 JavaScript、Three.js 和 Vite，保持模块简单、运行时资源本地化。

## 视觉方向

像一本安静的山野旅行手记：全屏低多边形雪景，象牙白雪面、灰蓝远山、深松绿植被、砖橙色滑雪服与按钮、暖黄色木屋灯光。首页使用错落的两行中文宋体大标题「雪境 / 漫游。」、轻量英文品牌标记与充足留白。保留「往山下滑，把自己交给下一片风景。」的轻松语气。

镜头采用稳定、略俯视的第三人称跟随视角。让滑雪者在画面下方，前方雪道和下一片风景清晰可见。HUD 用小型半透明面板显示本局距离、区域名和暂停按钮；暂停和摔倒结算沿用同一套温暖纸感弹层。

## 必须保留的玩法

1. 自动下坡，速度从 12 m/s 平滑加速至 22 m/s；A/D、左右方向键及横向拖动转向，松手后输入回中。
2. 空格或「小跳」按钮起跳，只能落地后再次起跳；可越过低矮岩石与木桩，松树必须绕开。
3. 碰撞后先播放摔倒动作，再展示本局距离。支持暂停、继续、R 重开、结算重试及「换个地点」。
4. 首页四个原生单选控件选择出发地：清晨松林、开阔雪坡、冰蓝山谷、暮色山间小镇。选择后实时切换背景与开始按钮文案；每次出发本局距离从 0 开始，前 100 m 无障碍，重开保留选择但更换路线种子。
5. 四区连续循环，每区 760 m，末尾 180 m 为渐变带。地形与景物根据各自的绝对里程取区域权重，下一片风景从远处接近，不能只把当前树木或背景瞬间换色。
6. 保留道路循迹辅助、冰面惯性、滑雪者倾身与跳跃动作、双雪痕、雪粉、飘雪、薄雾、木屋炊烟和移动缆车。
7. 失去窗口焦点或切换标签页自动暂停并清除输入。WebGL 不可用或上下文丢失时显示可操作的恢复提示。

## 代码入口

- `src/main.js`：状态机、输入、游戏循环、相机、灯光与自适应画质。
- `src/course.js`：区域常量、路线种子、地形高度、障碍生成与碰撞。
- `src/world.js`：分段地形、实例化景物、流式回收、冰面及缆车。
- `src/scenery.js` / `src/skier.js` / `src/effects.js`：景物几何、角色动作、特效。
- `src/style.css`：语义 CSS 变量、首页、HUD、弹层及响应式布局。
- `tests/course.test.js`：区域连续性、可通行性、碰撞与出发地保护距离。
- 本地工程以 `index.html` 为源码入口；Studio 提交包以 `index.template.html` 为源码入口，由 `scripts/build.mjs` 生成可静态访问的 `index.html`、`assets/` 和 `dist/`。

## 实现约束

- 优先复用现有组件、状态流和 CSS 变量；不要引入账号、付费、排行榜等需求之外的系统。
- 一个世界单位约一米。新造型先验证灰模比例和遮挡，再加细节、材质与光照。
- 地形每段 64 m，保持前方预加载与后方释放，正常保留约 12–13 段；复用几何、材质、InstancedMesh 和固定粒子池。
- 按帧间隔更新运动，限制过大的时间步长。维持窄屏粒子预算、像素比与阴影降级策略。
- 按钮必须同时支持指针与键盘激活，焦点可见，弹层约束焦点，恢复提示不应被游戏快捷键或焦点陷阱阻挡。
- 保留 UI 的 reduced-motion 适配；真实滑行仍由用户主动开始。
- 不依赖在线字体、CDN、API Key 或外部模型。保留 Three.js MIT 许可；应用自身许可未单独指定，不要擅自补写授权承诺。
- 调试桥只在开发环境存在，生产包不得暴露 `window.__snowbound`。生产资源使用相对路径，支持子目录静态托管。

## 完成标准

1. `npm ci`、`npm test`、`npm run build` 成功；说明构建告警。
2. 亲自用浏览器验证全部四个出发地、键盘和拖动转向、跳跃越障、碰撞结算、暂停继续、重开及换地点。
3. 验证标签切换自动暂停、WebGL 恢复、手机尺寸布局和键盘焦点行为。
4. 验证场景连续过渡和循环，保留四区及至少一张过渡截图；检查内存回收与控制台错误。
5. 在静态 HTTP 服务上测试生产构建，确认没有开发调试桥和外部运行请求；真实手机性能不得用桌面模拟结果代替。
6. 更新 README、QA 与本 Prompt 涉及的行为说明。不能用「应该可用」代替实测结论。

## 如需提交 Studio 模板

先读目标仓库最新 `docs/template-publishing.md`。从最新 `main` 建分支，将源码、静态产物、许可与说明放入 `sites/snowbound/`；更新根 `catalog.json` 的 `games` 分类登记。

录制当前生产版本的真实画面，提交独立 `preview/cover.png` 与 `preview/video.mp4`，二者比例一致。视频 H.264、5–30 秒、无音轨、faststart，建议宽 1280 px / 30 fps；不要把截图动画当作运行录屏。

运行仓库目录校验和媒体检查，在浏览器实测视频播放与拖动进度。提交前再次 fetch upstream，检查 diff、分支合并和同名 ID 冲突。创建 PR 后确认 GitHub 的可合并状态；合并后由 Studio 环境负责人将服务端固定到包含源码、目录和素材的同一个已合并完整 SHA。
